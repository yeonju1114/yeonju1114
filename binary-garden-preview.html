Tomcat 10.1 SSL 인증서 교체 절차 (PKCS12)

2026. 11. 10약 4분수정 2026. 11. 15

인증서 체인 순서가 틀리면 핸드셰이크에서 실패합니다. keystore 생성, 서버 설정 반영, 재기동 후 검증까지 순서대로 정리합니다.

전제조건

기준 버전: Tomcat 10.1 · keytool이 JDK 17에 포함되어 있어야 합니다.

교체 전에 기존 keystore를 반드시 백업하세요. 롤백 포인트가 됩니다.

절차

  1. 체인 파일을 서버 → 중간 → 루트 순서로 합칩니다.
  2. openssl pkcs12로 keystore를 생성합니다.
  3. server.xml의 certificateKeystoreFile을 갱신합니다.
  4. 재기동하고 핸드셰이크를 확인합니다.
bash
# 체인 합치기 후 PKCS12 생성
openssl pkcs12 -export -inkey server.key -in fullchain.pem \
  -name tomcat -out server.p12 -passout pass:<KEYSTORE_PW>
output
Certificate chain
 0 s:CN = www.example.com
 1 s:C = US, O = Example CA
Verify return code: 0 (ok)

server.xml 파라미터

PARAMETER기본값권장값
sslProtocolTLSTLSv1.2+
certificateKeystoreTypeJKSPKCS12

증상

접속 시 PKIX path building failed

원인

체인 순서 오류

해결

서버 → 중간 → 루트 순서로 다시 합칩니다.

체인 순서가 틀리면 접속이 끊깁니다.

재기동 없이 반영하려면 reloadTlsConfig를 사용합니다.
